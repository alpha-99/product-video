## Worker 启动后自己退出（用户贴日志，已修复）

- 现象：`npm run worker` 打印 `[worker] ready` 后，出现 `Error: write EPIPE`（堆栈在 `@remotion/renderer/dist/prespawn-ffmpeg.js` 的 `writeFrame` / `renderFramesProc.onFrame`），带 `triggerUncaughtException(err, true /* fromPromise */)`，进程直接退出；同时刷 `Timed out fetching a new connection from the connection pool (timeout: 10, connection limit: 9)`；另有 3 个历史任务反复报 `素材地址不受信任：仅允许受控 data URL 或 uploads/{userId}/ 相对路径` → retry_scheduled ×2 → failed。
- 根因：
  1. EPIPE 来自 Remotion 预启动 ffmpeg 的写帧通道，是**内部未被 await 的 Promise** 抛出的，worker 主循环 `loop()` 的 try/catch 抓不到，Node 默认 `--unhandled-rejections=throw` 直接终止进程。这才是「自己退出」的直接原因。
  2. Prisma 默认按 CPU 算 `connection_limit=9`，Web / Worker / 测试多进程一起超过 Supavisor session pool 上限 15，`pool_timeout=10` 在跨境抖动下必然超时。
  3. 素材报错是上一轮 P1-08 收紧渲染层后的**历史快照**：站内相对路径（如项目占位图）不在 `uploads/{userId}/` 下即被硬拒。查库确认当前仅剩 2 个任务且 imageUrl 都是合法 uploads 路径，那 3 个失败任务已被清理；另有一个 `4aa39a38…` 孤儿任务 `processing/attempt=3`。
- 修复：
  - `src/worker/index.ts`：加 `unhandledRejection` / `uncaughtException` 全局兜底 `reportUnexpected()`（记累计次数 + 完整堆栈 + EPIPE 专项提示，不退出进程）；去掉 `loop().finally(() => process.exit(0))`，避免 SIGTERM 时截断 "stopped" 心跳写库，改为 `.catch()` 设 `exitCode=1` 后让事件循环自然排空。
  - `src/lib/db.ts`：`prismaUrl()` 导出，追加 `connection_limit=4` / `pool_timeout=20`（连同原有 `connect_timeout=15`），已显式配置的参数不覆盖，可用 `PV_DB_CONNECTION_LIMIT` / `PV_DB_POOL_TIMEOUT` 覆盖。
  - `src/lib/renderer.ts`：`resolveAssetForRender(src, field)` 增加字段名参数，被拒时错误消息带 `字段名=被拒值（截断 120 字）`；加 `PUBLIC_PLACEHOLDER_ASSETS` 白名单（`placeholder-product.svg` 从 `public/` 读后内联成 data URL），兼容历史快照且不放宽外部 URL / 绝对路径边界；`renderVideo` 开头先 `rm(tempDir)` 再 `mkdir`，清掉上次崩溃残留的 `temp.mp4`，避免 Windows 文件占用让 ffmpeg 一启动就 EPIPE 形成重启循环。
  - 新增 `tests/worker-resilience.test.ts`（7 例：静态守卫 + prismaUrl 参数 + 占位图/错误消息行为），已加入 `npm test`。
