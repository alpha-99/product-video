2. 产品业务逻辑

本节把 PRD 中的功能点串成可开发的业务逻辑：先给主流程与角色泳道，再定义任务状态机、额度逻辑、规则归类、数据关系与权限模型。

2.1 核心业务主流程与泳道

视频生成是产品的核心价值链路，涉及用户、前端、API/数据库、Worker/Remotion、文件系统五方协作。

用户        前端(Next.js)      API + PostgreSQL        Worker + Remotion      本地磁盘
 |              |                    |                       |                  |
 | 选商品/模板   |                    |                       |                  |
 |------------->|  读取商品/模板       |                       |                  |
 |              |------------------->|                       |                  |
 | 生成AI文案    |                    |                       |                  |
 |------------->|  AI 文案请求         |                       |                  |
 |              |------------------->| (调用 AI,Schema 校验)   |                  |
 | 编辑/预览     |  Remotion Player   |                       |                  |
 |<-----------------------------------------------------------------------------|
 | 提交生成      |                    |                       |                  |
 |------------->|  建任务+扣额度(事务) |                       |                  |
 |              |------------------->|  status=pending        |                  |
 |              |                    |<--领取锁定(行锁)---------|                  |
 |              |                    |  status=processing     |  组装参数/渲染     |
 |              |                    |---------------------->|  写 input.json      |
 |              |                    |                       |----------------->| temp.mp4
 |              |                    |                       |  生成缩略图/移动文件 |
 |              |                    |                       |----------------->| videos/{job}.mp4
 |              |                    |<--completed/failed-----|                  |
 | 查看/下载     |  轮询任务状态        |                       |                  |
 |------------->|------------------->|  鉴权返回文件          |                  |
 |<---------------------------------|-------------------------------------------|

流程要点：

- 异步边界：提交后立即返回任务 ID，渲染不阻塞 HTTP 请求；前端通过轮询或定时刷新获取状态。

- 一致性边界：额度扣减与任务创建在同一个数据库事务内完成；视频文件与数据库记录需要保持一致。

- 失败边界：渲染失败记录错误信息，任务进入 failed 并返还额度；用户可重新生成。

2.2 视频任务状态机

video_jobs.status 是业务核心状态，采用单向流转防止状态回跳。状态集合沿用 PRD：pending、processing、completed、failed、cancelled。

当前状态触发事件迁移条件目标状态伴随动作
（无）用户提交生成文案通过 Schema 校验且额度 ≥1pending创建任务、事务内原子扣减 1 次额度
pendingWorker 领取任务行锁锁定成功（同一任务仅一个 Worker）processing写入领取记录、开始渲染
processing渲染成功MP4 落盘且缩略图生成completed写 output_path、生成缩略图、completed_at
processing渲染失败渲染异常/超时failed写 error_message、返还额度
pending / processing用户取消用户主动取消且任务未 completedcancelled停止/丢弃任务、返还额度
failed / cancelled用户重新生成额度 ≥1pending以原参数创建新任务、重新占用额度

状态—允许操作矩阵：

状态预览结果下载重新生成取消删除
pending否否否是是
processing否否是是是
completed是是是否是
failed否否是否是
cancelled否否是否是

稳定性约束：Worker 异常退出后任务不得永久停留在 processing；通过任务超时扫描将超时任务转入 failed 并返还额度。

2.3 额度与用量逻辑

额度是连接产品体验与商业化的关键规则，必须保证原子性与可追溯。V1.0 先实现免费额度与简单次数限制，订阅支付后置。

规则项口径
初始额度新用户 3 次（免费体验）
扣减时机成功创建 pending 任务时扣减，与任务创建同事务
原子性采用条件更新（如 remaining > 0 才扣减）或等效锁机制，防止并发重复请求超额生成
幂等同一请求方幂等键重复提交，不重复建任务、不重复扣额度
返还时机任务终态为 failed 或 cancelled 时返还 1 次
消耗口径1 条视频 = 1 次额度；重新生成视为新任务重新占用
用量记录每次生成写入 usage_records，含 user_id、video_job_id、usage_type、amount
不足处理额度为 0 时阻止提交，提示升级；不创建任务、不扣减

说明：BR-009（失败任务返还额度）与 BR-006（同任务单 Worker）共同保证「不重复扣、不重复渲染」；订阅套餐额度（Starter 30 / Pro 100 / Agency 250）在支付能力上线后接入，去水印与额度提升同步生效。

3.3 页面流转

以任务为单位梳理跳转条件与返回路径。

创作视频任务：
登录 → Dashboard →[新建视频]→ 商品管理/选择商品 → 模板选择 → 视频创作(向导) → 视频管理 → 下载

管理任务：
Dashboard →[最近视频]→ 视频管理 → 预览/下载/重新生成/删除

配置任务：
用户菜单 → 我的额度 →（额度不足时）升级提示；用户菜单 → 账号设置

返回路径：向导每一步可返回上一步；提交后不可回退到编辑，需通过「重新生成」另起任务；删除操作可取消。

3.4 关键页面线框思路

页面：视频创作页（核心页）

- 页面目标：让用户在不离开页面的情况下完成文案编辑、参数配置、预览与提交。

- 布局思路：顶部步骤条（选商品 → 选模板 → 文案 → 参数 → 预览 → 提交）；左侧为文案与参数表单，右侧为竖屏 9:16 预览区；底部为「上一步 / 生成文案 / 提交生成」操作栏。

- 交互说明：文案字段旁提供「重新生成」；参数变更实时反映到预览；文案超限或必填缺失时提交按钮禁用并提示原因。

页面：商品管理页

- 页面目标：快速维护创作素材。

- 布局思路：顶部「新增商品」按钮；列表卡片展示主图、名称、卖点数、创建时间；每行含编辑/删除。

- 交互说明：删除需二次确认；上传区实时校验格式与大小并显示进度；空状态引导新增。

页面：模板选择页

- 页面目标：按营销目的选择模板。

- 布局思路：模板卡片网格，含预览缩略图、名称、时长（15/20 秒）、适用场景；停用的模板不展示。

- 交互说明：点击卡片进入创作并锁定模板；可返回更换。

页面：视频管理页

- 页面目标：跟踪生成结果并下载。

- 布局思路：列表/卡片展示封面、名称、关联商品、模板、状态、时间；状态用标签区分；行操作含预览、下载、重新生成、删除。

- 交互说明：未完成任务显示进度状态且预览/下载置灰；失败项显示错误原因并提供重新生成；状态定时刷新。

页面：Dashboard

- 页面目标：一眼看到额度与最近产出，并提供主行动入口。

- 布局思路：顶部剩余额度卡片；「新建视频」主按钮；下方最近视频列表。

- 交互说明：额度为 0 时主按钮旁显示升级提示；无视频时展示空状态引导。

页面：登录注册页

- 页面目标：最小化注册阻力。

- 布局思路：居中表单，邮箱、密码、登录/注册切换；新用户免费额度说明。

- 交互说明：校验错误就近提示；注册成功直接进入 Dashboard。

3.5 交互设计原则与四态

原则落地要求
状态完整空、加载、错误、边界（超限/超长/无权限）四态均有设计
反馈及时每次操作有结果反馈：成功、失败、进行中
操作可逆删除需二次确认；向导可返回上一步
一致性相同操作在各页面文案与位置一致
容错引导输入错误指出位置并给修正建议，不只用红框
无障碍关键操作支持键盘可达，文字与背景满足基本对比度

四态设计示例：

状态商品管理页视频创作页视频管理页
空无商品，引导新增无商品/无模板，引导先创建无视频，引导新建
加载列表骨架屏生成文案时按钮 Loading、预览占位状态轮询中显示进度
错误上传失败提示格式/大小原因AI 失败提示重试、Schema 失败提示字段失败任务显示错误原因 + 重试
边界图片 >10 MB 拦截文案超限拦截提交额度为 0 提示升级

4. 交互流程

本节把创作向导的每一步拆成「用户操作 / 系统反馈 / 校验 / 可回退」四列，并汇总主分支异常流程与关键交互说明。

4.1 视频创作向导交互流程

步骤用户操作系统反馈校验点可回退
1 选择商品从列表选择或现场新建商品显示已选商品主图与摘要必选；新建商品需通过图片校验是
2 选择模板点击模板卡片锁定模板并展示时长/规格仅已启用模板可选是（返回第 1 步）
3 生成文案点击「生成文案」展示标题/副标题/卖点/CTA，可编辑、可重新生成Schema 校验、长度限制、不编造功效/认证是
4 配置参数选品牌色、Logo、背景音乐预览实时更新可选项缺省用模板默认值是
5 视频预览查看 9:16 预览Remotion Player 播放必填参数完整方可进入下一步是
6 提交生成点击「提交生成」创建任务、扣额度、跳转视频管理页额度 ≥1、文案通过校验、幂等防重否（提交后走重新生成）

4.2 主流程、分支流程与异常流程

类型流程关键节点
主流程登录 → Dashboard → 选商品 → 选模板 → AI 文案 → 编辑预览 → 提交 → 视频管理 → 下载全链路无阻断
分支 A创作中现场新建商品新建成功后自动回填为当前商品
分支 BAI 文案不满意重新生成；已手工编辑字段默认保留
分支 C品牌项未配置使用模板默认值，不阻断提交
分支 D额度不足阻止提交，提示升级路径
异常 A图片格式/大小错误上传即校验并提示原因，不落盘
异常 BAI 生成失败提示「重新生成」，不扣额度
异常 C渲染失败任务转 failed、记录错误、返还额度、提供重试
异常 DWorker 异常退出超时扫描将 processing 转 failed 并返还额度
异常 E越权访问查询带 user_id 过滤，返回拒绝，不泄露文件
异常 F磁盘不足告警并暂停提交，避免写盘失败

4.3 关键交互说明

交互点说明
任务进度反馈前端定时轮询或刷新任务状态；状态文案与状态机严格一致（pending 等待 / processing 渲染中 / completed 完成 / failed 失败 / cancelled 已取消）
失败重试失败任务展示错误原因；点击重新生成时先按规则返还原占用额度，再创建新任务占用 1 次
额度提示创作页常驻显示剩余额度；不足时禁用提交并说明升级后去水印、提额度
二次确认删除商品、删除视频均需二次确认；取消则无副作用
预览与提交分离预览使用 Remotion Player（低分辨率可降成本），提交后才走完整渲染生成 MP4
文案合规AI 输出不得编造商品功效、认证或未经证实的宣传声明；用户可编辑并承担最终确认
