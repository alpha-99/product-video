1. 产品概述

本章说明产品的背景、定位与核心价值，明确 ProductVideo AI 要解决的市场问题。

1.1 产品背景

当前中小电商商家需要持续制作商品营销视频，用于 TikTok、Instagram Reels、YouTube Shorts 等渠道。但传统视频制作存在以下问题：

  • 视频制作需要一定的剪辑和设计能力。
  • 外包制作成本较高。
  • 商品上新和促销时，需要反复制作视频。
  • 不同商品的视频风格难以保持一致。
  • 批量生产视频效率低。

ProductVideo AI 通过商品信息参数化和 Remotion 模板渲染，将商品图片和商品信息转换成标准化的营销视频。

1.2 产品定位

面向中小电商卖家的商品营销视频自动生成工具。

产品不是通用视频编辑器，也不是开放式 AI 文生视频平台，而是通过固定的高质量模板，帮助商家快速生产商品营销视频。

1.3 产品价值

价值说明
降低制作门槛不需要专业剪辑能力
提高制作效率几分钟生成商品视频
降低制作成本减少重复外包制作
统一品牌风格使用可复用的视频模板
支持批量生产多商品复用相同模板

2. 产品目标与范围

本章定义 MVP 阶段要验证的核心问题、成功指标以及本期的功能边界。

2.1 MVP 产品目标

第一阶段重点验证三个问题：

  • 用户能否通过简单操作生成商品视频？
  • 生成的视频是否达到商家实际发布的质量要求？
  • 用户是否愿意为视频生成服务持续付费？

2.2 MVP 成功指标

视频生成成功率目标 95% 以上
月度收入后续逐步达到 $500

  以上属于产品验证目标，不代表上线后必然达到。

  • 场景 B：商品卖点介绍 —— 用户上传商品图片和商品描述，AI 提取三个卖点，生成商品介绍视频。

  • 场景 D：品牌展示 —— 用户配置品牌名称、Logo、品牌色和商品图片，生成统一品牌视觉的视频。

  • 用户只能查看自己的商品和视频任务。

5.2 商品管理（P0）

商品管理是视频生成的基础。商品信息字段：

字段必填说明
商品名称是商品标题
商品图片是商品主图
商品描述否商品介绍
商品价格否商品价格
商品卖点否最多 5 个
品牌名称否商品品牌
品牌 Logo否品牌图片
品牌颜色否品牌主色

功能要求：

  • 新增商品。
  • 编辑商品。
  • 删除商品。
  • 查看商品列表。
  • 上传和替换商品图片。
  • 商品信息可以重复用于多个视频。

验收标准：

  • 支持 JPG、PNG、WebP 格式。
  • 图片大小限制建议为 10 MB。
  • 图片上传后保存到服务器本地磁盘。
  • 图片与用户 ID 关联。
  • 删除商品时，不能误删该商品关联的其他用户文件。

5.3 AI 商品文案生成（P0）

AI 根据商品资料生成视频营销文案。

输入：

{
  "productName": "Hydrating Face Cream",
  "description": "Daily moisturizing skincare cream",
  "sellingPoints": [
    "Lightweight texture",
    "Daily skincare"
  ],
  "price": "$29.99"
}

输出：

{
  "videoTitle": "Your Daily Hydration Essential",
  "subtitle": "Lightweight Care for Everyday Skin",
  "sellingPoints": [
    "Lightweight Texture",
    "Daily Moisture",
    "Easy Everyday Care"
  ],
  "cta": "Discover More"
}

功能要求：

  • 自动生成视频标题。
  • 自动生成副标题。
  • 自动生成商品卖点。
  • 自动生成 CTA。
  • 用户可以编辑 AI 生成的内容。
  • 支持重新生成。
  • 文案长度必须满足模板限制。
  • 不允许 AI 擅自编造商品功效、认证或未经证实的宣传声明。

验收标准：

  • AI 返回符合预定义 JSON Schema 的数据。
  • AI 生成失败时可以重新请求。
  • 文案经过用户确认后才进入视频渲染。

5.5 视频创作流程（P0）

这是整个产品最核心的用户操作流程，采用视频创作向导：

  1. 选择商品：从商品列表选择商品，或直接创建新商品。
  2. 选择视频模板：从新品展示、卖点介绍、促销活动、高级品牌展示中选择。
  3. 生成营销文案：AI 自动生成标题、字幕和 CTA，用户可以修改。
  4. 配置视频参数：选择品牌颜色、Logo、背景音乐等可配置项。
  5. 视频预览：使用 Remotion Player 预览效果。
  6. 提交视频生成：创建异步渲染任务。
  7. 查看生成结果：生成完成后展示 MP4 视频和下载入口。

5.6 视频渲染（P0）

功能要求：

  • 根据模板 ID 加载对应 Composition。
  • 根据商品和文案参数生成视频。
  • 使用 Remotion 执行渲染。
  • 视频渲染过程中不能阻塞 HTTP 请求。
  • 支持任务失败状态和重新生成。
  • 渲染成功后生成视频缩略图。
  • 视频保存到本地文件系统。

渲染任务状态：

状态说明
pending等待执行
processing正在渲染
completed渲染完成
failed渲染失败
cancelled用户取消

验收标准：

  • 同一任务不能被多个 Worker 重复领取。
  • 渲染失败时记录错误信息。
  • 失败任务可以重新执行。
  • 用户可以看到实时或定时更新的任务状态。
  • 渲染完成后视频可以正常播放和下载。

8. 非功能性需求

本章从性能、安全与稳定性三个维度规定产品的非功能性要求。

8.1 性能

项目目标
页面首次加载目标 3 秒以内
API 响应常规接口目标 500ms 以内
视频渲染15～20 秒视频目标 3 分钟以内
并发渲染MVP 单任务
图片上传单文件最大 10 MB

渲染耗时取决于服务器配置、模板复杂度和素材，需通过实际压测确认。

8.2 安全

  • 所有业务 API 必须验证用户身份。
  • 所有商品和视频查询必须校验用户归属。
  • 文件上传必须校验文件格式和大小。
  • 防止路径穿越和任意文件读取。
  • 不允许用户直接访问其他用户的文件。
  • API 设置合理的频率限制。
  • AI API Key 只能保存在服务端。
  • 视频下载使用鉴权接口。

8.3 稳定性

  • Worker 异常退出后，任务不能永久停留在 processing。
  • 设置任务超时和失败恢复机制。
  • 定期清理临时文件。
  • 对磁盘使用量进行监控。
  • 数据库定期备份。
  • 对商品原始图片和重要视频建立备份策略。

9. 技术架构约束

本 PRD 与已确定的简化架构保持一致。

层次技术方案

UITailwind CSS + shadcn/ui
后端Next.js API
数据库Supabase PostgreSQL
身份认证Supabase Auth
视频模板Remotion
视频编码FFmpeg
异步任务PostgreSQL + Node.js Worker
文件存储VPS 本地磁盘
AIOpenAI / Claude
Web 服务Nginx

明确不使用 Redis、BullMQ、S3、R2、AWS Lambda、Kubernetes 和微服务。

  重要技术约束：Next.js Web 进程与 Remotion Worker 虽然共享代码仓库，但必须作为独立进程运行。Worker 使用 PostgreSQL 领取任务，并通过事务锁避免重复执行。
