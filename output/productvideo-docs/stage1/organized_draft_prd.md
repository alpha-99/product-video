# ProductVideo AI 产品需求文档

基于前面确定的技术架构和创业方向，整理一版可以直接用于后续 UI 设计、数据库设计和 AI 辅助编码的 PRD。本版定位为 V1.0 MVP 产品需求文档，优先保证核心视频生成链路可用，不把复杂的 SaaS 功能放进第一期。

| 项目 | 内容 |
|------|------|
| 产品类型 | Web SaaS |
| 目标用户 | 中小电商卖家、电商品牌 |
| 首期垂直品类 | 美妆护肤 |
| 视频风格 | 高级品牌感 |
| 核心能力 | 商品资料转营销短视频 |
| 视频规格 | 9:16，1080 × 1920 |
| 视频时长 | 15～20 秒 |
| 商业目标 | 月收入 $500～2,000 |
| 开发周期 | 30 天 MVP |

## 1. 产品概述

### 1.1 产品背景

当前中小电商商家需要持续制作商品营销视频，用于 TikTok、Instagram Reels、YouTube Shorts 等渠道。但传统视频制作存在以下问题：

- 视频制作需要一定的剪辑和设计能力。
- 外包制作成本较高。
- 商品上新和促销时，需要反复制作视频。
- 不同商品的视频风格难以保持一致。
- 批量生产视频效率低。

ProductVideo AI 通过商品信息参数化和 Remotion 模板渲染，将商品图片和商品信息转换成标准化的营销视频。

### 1.2 产品定位

面向中小电商卖家的商品营销视频自动生成工具。

产品不是通用视频编辑器，也不是开放式 AI 文生视频平台，而是通过固定的高质量模板，帮助商家快速生产商品营销视频。

### 1.3 产品价值

| 价值 | 说明 |
|------|------|
| 降低制作门槛 | 不需要专业剪辑能力 |
| 提高制作效率 | 几分钟生成商品视频 |
| 降低制作成本 | 减少重复外包制作 |
| 统一品牌风格 | 使用可复用的视频模板 |
| 支持批量生产 | 多商品复用相同模板 |

## 2. 产品目标与范围

### 2.1 MVP 产品目标

第一阶段重点验证三个问题：

- 用户能否通过简单操作生成商品视频？
- 生成的视频是否达到商家实际发布的质量要求？
- 用户是否愿意为视频生成服务持续付费？

### 2.2 MVP 成功指标

| 指标 | 目标 |
|------|------|
| 视频模板 | 3～5 套 |
| 真实试用客户 | 5～10 家 |
| 生成视频数量 | 100 条 |
| 付费试用客户 | 至少 3 家 |
| 单条视频生成时间 | 目标 3 分钟以内 |
| 视频生成成功率 | 目标 95% 以上 |
| 月度收入 | 后续逐步达到 $500 |

以上属于产品验证目标，不代表上线后必然达到。

### 2.3 功能范围

**V1.0 纳入**：

- 用户注册和登录。
- 商品信息管理。
- 商品图片上传。
- AI 营销文案生成。
- 视频模板选择。
- 视频参数编辑。
- 视频预览。
- 视频异步生成。
- 视频任务管理。
- 视频下载。
- 基础使用额度统计。

**V1.0 暂不纳入**：

- AI 文生视频、图生视频。
- 数字人和口播。
- 时间轴编辑器。
- Shopify 深度集成。
- TikTok 自动发布。
- 多人团队协作。
- 用户自定义上传 Remotion 代码。
- 复杂营销数据分析。

## 3. 用户角色与使用场景

### 3.1 用户角色

| 角色 | 描述 | 主要需求 |
|------|------|----------|
| 普通用户 | 电商商家 | 生成商品视频 |
| 付费用户 | 订阅客户 | 获取更多视频额度 |
| 管理员 | 产品运营者 | 管理模板和用户 |

V1.0 不需要复杂的组织、团队和角色权限体系。

### 3.2 典型使用场景

- **场景 A：新品发布** —— 用户上传护肤品图片，填写名称和价格，选择新品展示模板，生成一条新品宣传视频。
- **场景 B：商品卖点介绍** —— 用户上传商品图片和商品描述，AI 提取三个卖点，生成商品介绍视频。
- **场景 C：促销活动** —— 用户填写商品价格、促销价格和优惠信息，生成促销视频。
- **场景 D：品牌展示** —— 用户配置品牌名称、Logo、品牌色和商品图片，生成统一品牌视觉的视频。

## 5. 详细功能需求

### 5.1 用户管理（P0）

| 功能 | 需求说明 |
|------|----------|
| 用户注册 | 邮箱注册 |
| 用户登录 | 邮箱和密码登录 |
| 用户退出 | 清除登录会话 |
| 用户信息 | 查看和修改基本信息 |
| 用户额度 | 查看剩余视频生成次数 |

**验收标准**：

- 用户可以正常注册、登录和退出。
- 未登录用户不能访问受保护页面。
- 用户只能查看自己的商品和视频任务。

### 5.2 商品管理（P0）

商品管理是视频生成的基础。商品信息字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| 商品名称 | 是 | 商品标题 |
| 商品图片 | 是 | 商品主图 |
| 商品描述 | 否 | 商品介绍 |
| 商品价格 | 否 | 商品价格 |
| 商品卖点 | 否 | 最多 5 个 |
| 品牌名称 | 否 | 商品品牌 |
| 品牌 Logo | 否 | 品牌图片 |
| 品牌颜色 | 否 | 品牌主色 |

**功能要求**：

- 新增商品。
- 编辑商品。
- 删除商品。
- 查看商品列表。
- 上传和替换商品图片。
- 商品信息可以重复用于多个视频。

**验收标准**：

- 支持 JPG、PNG、WebP 格式。
- 图片大小限制建议为 10 MB。
- 图片上传后保存到服务器本地磁盘。
- 图片与用户 ID 关联。
- 删除商品时，不能误删该商品关联的其他用户文件。

### 5.3 AI 商品文案生成（P0）

AI 根据商品资料生成视频营销文案。

**输入**：

```json
{
  "productName": "Hydrating Face Cream",
  "description": "Daily moisturizing skincare cream",
  "sellingPoints": [
    "Lightweight texture",
    "Daily skincare"
  ],
  "price": "$29.99"
}
```

**输出**：

```json
{
  "videoTitle": "Your Daily Hydration Essential",
  "subtitle": "Lightweight Care for Everyday Skin",
  "sellingPoints": [
    "Lightweight Texture",
    "Daily Moisture",
    "Easy Everyday Care"
  ],
  "cta": "Discover More"
}
```

**功能要求**：

- 自动生成视频标题。
- 自动生成副标题。
- 自动生成商品卖点。
- 自动生成 CTA。
- 用户可以编辑 AI 生成的内容。
- 支持重新生成。
- 文案长度必须满足模板限制。
- 不允许 AI 擅自编造商品功效、认证或未经证实的宣传声明。

**验收标准**：

- AI 返回符合预定义 JSON Schema 的数据。
- AI 生成失败时可以重新请求。
- 文案经过用户确认后才进入视频渲染。

| 模板 | 名称 | 主要内容 | 建议时长 |
|------|------|----------|----------|

| 模板 B | Product Highlight 卖点介绍 | 商品图片、卖点动画、动态字幕 | 20 秒 |
| 模板 C | Product Sale 促销活动 | 原价、折扣价、优惠文案、购买 CTA | 15 秒 |
| 模板 D | Premium Showcase 高级品牌展示 | 品牌视觉、商品特写、优雅转场、品牌宣传文案 | 20 秒 |

**模板统一规格**：

| 属性 | 规格 |
|------|------|
| 画面比例 | 9:16 |
| 输出分辨率 | 1080 × 1920 |
| 帧率 | 30 FPS |

| 模板参数 | JSON |

### 5.5 视频创作流程（P0）

这是整个产品最核心的用户操作流程，采用视频创作向导：

1. **选择商品**：从商品列表选择商品，或直接创建新商品。
2. **选择视频模板**：从新品展示、卖点介绍、促销活动、高级品牌展示中选择。
3. **生成营销文案**：AI 自动生成标题、字幕和 CTA，用户可以修改。
4. **配置视频参数**：选择品牌颜色、Logo、背景音乐等可配置项。
5. **视频预览**：使用 Remotion Player 预览效果。
6. **提交视频生成**：创建异步渲染任务。
7. **查看生成结果**：生成完成后展示 MP4 视频和下载入口。

### 5.6 视频渲染（P0）

**功能要求**：

- 根据模板 ID 加载对应 Composition。
- 根据商品和文案参数生成视频。
- 使用 Remotion 执行渲染。
- 视频渲染过程中不能阻塞 HTTP 请求。
- 支持任务失败状态和重新生成。
- 渲染成功后生成视频缩略图。
- 视频保存到本地文件系统。

**渲染任务状态**：

| 状态 | 说明 |
|------|------|
| pending | 等待执行 |
| processing | 正在渲染 |
| completed | 渲染完成 |
| failed | 渲染失败 |
| cancelled | 用户取消 |

**验收标准**：

- 同一任务不能被多个 Worker 重复领取。
- 渲染失败时记录错误信息。
- 失败任务可以重新执行。
- 用户可以看到实时或定时更新的任务状态。
- 渲染完成后视频可以正常播放和下载。

### 5.7 视频管理（P0）

| 功能 | 需求说明 |
|------|----------|
| 视频列表 | 展示用户生成的视频 |
| 视频预览 | 在线播放 MP4 |

| 视频详情 | 查看模板、商品和生成时间 |
| 视频删除 | 删除视频及相关文件 |
| 重新生成 | 使用原始参数重新生成 |

视频列表展示：视频封面、视频名称、关联商品、使用模板、生成时间、视频状态、下载和删除操作。

### 5.8 用量管理（P1）

MVP 初期可以只提供免费体验额度和简单的生成次数限制。

| 功能 | 说明 |
|------|------|
| 免费额度 | 新用户获得 3 次体验机会 |
| 生成扣减 | 成功提交生成任务后占用额度 |
| 失败返还 | 任务最终失败时返还额度 |
| 额度查询 | 显示剩余次数 |
| 用量记录 | 记录每次视频生成 |

注意：额度扣减必须具备原子性，避免重复请求造成超额生成。

## 7. 核心业务规则

| 编号 | 业务规则 |
|------|----------|
| BR-001 | 用户只能访问自己的商品和视频 |
| BR-002 | 每个视频必须关联一个模板 |
| BR-003 | 每个视频必须有合法的渲染参数 |
| BR-004 | 文案必须通过 JSON Schema 校验 |
| BR-005 | 任务提交后异步执行 |
| BR-006 | 同一任务只能被一个 Worker 领取 |
| BR-007 | 渲染完成后才标记为 completed |
| BR-008 | 失败任务可以重试 |
| BR-009 | 失败任务返还已占用的生成额度 |
| BR-010 | 视频文件和数据库记录需要保持一致 |
| BR-011 | 删除视频时清理对应本地文件 |
| BR-012 | 不允许用户执行或上传任意 Remotion 代码 |

## 8. 非功能性需求

### 8.1 性能

| 项目 | 目标 |
|------|------|
| 页面首次加载 | 目标 3 秒以内 |
| API 响应 | 常规接口目标 500ms 以内 |
| 视频渲染 | 15～20 秒视频目标 3 分钟以内 |
| 并发渲染 | MVP 单任务 |
| 图片上传 | 单文件最大 10 MB |

渲染耗时取决于服务器配置、模板复杂度和素材，需通过实际压测确认。

### 8.2 安全

- 所有业务 API 必须验证用户身份。
- 所有商品和视频查询必须校验用户归属。
- 文件上传必须校验文件格式和大小。
- 防止路径穿越和任意文件读取。
- 不允许用户直接访问其他用户的文件。
- API 设置合理的频率限制。
- AI API Key 只能保存在服务端。
- 视频下载使用鉴权接口。

### 8.3 稳定性

- Worker 异常退出后，任务不能永久停留在 processing。
- 设置任务超时和失败恢复机制。
- 定期清理临时文件。
- 对磁盘使用量进行监控。
- 数据库定期备份。
- 对商品原始图片和重要视频建立备份策略。

## 9. 技术架构约束

本 PRD 与已确定的简化架构保持一致。

| 层次 | 技术方案 |
|------|----------|
| Web 前端 | Next.js + React |
| UI | Tailwind CSS + shadcn/ui |
| 后端 | Next.js API |
| 数据库 | Supabase PostgreSQL |
| 身份认证 | Supabase Auth |
| 视频模板 | Remotion |
| 视频编码 | FFmpeg |
| 异步任务 | PostgreSQL + Node.js Worker |
| 文件存储 | VPS 本地磁盘 |
| AI | OpenAI / Claude |
| Web 服务 | Nginx |
| 部署 | Ubuntu VPS |

明确不使用 Redis、BullMQ、S3、R2、AWS Lambda、Kubernetes 和微服务。

**重要技术约束**：Next.js Web 进程与 Remotion Worker 虽然共享代码仓库，但必须作为独立进程运行。Worker 使用 PostgreSQL 领取任务，并通过事务锁避免重复执行。

## 10. 数据库实体关系

核心数据模型：

| 实体 | 说明 |
|------|------|
| User | 用户身份与账号信息 |
| Product | 商品信息和图片路径 |
| Subscription | 用户订阅和套餐 |
| VideoTemplate | 模板定义和配置 |
| UsageRecord | 视频生成额度记录 |
| VideoJob | 关联 User、Product、VideoTemplate，保存渲染状态、参数和输出文件路径 |

每个用户可以拥有多个商品和视频任务；每个视频任务关联一个商品和一个模板。

## 13. 产品核心指标

上线后重点关注：

| 指标 | 说明 |
|------|------|
| 注册转化率 | 访问者中注册用户比例 |
| 首次生成率 | 注册用户中成功生成视频的比例 |
| 视频成功率 | 成功渲染任务 / 总任务 |
| 视频下载率 | 下载视频用户 / 生成视频用户 |
| 付费转化率 | 付费用户 / 注册用户 |
| 用户留存率 | 持续使用产品的用户比例 |
| 单条视频成本 | AI、CPU、磁盘等成本 |

其中最重要的三个指标是：首次生成率、视频下载率和付费转化率。

## 14. 产品决策总结

**V1.0 产品范围最终确认**：

| 项目 | 内容 |
|------|------|
| 产品定位 | 美妆护肤商品视频生成器 |
| 核心能力 | 商品资料转短视频 |
| 视频风格 | 高级品牌感 |
| 视频引擎 | Remotion |
| 数据库 | Supabase PostgreSQL |
| 文件存储 | 本地磁盘 |
| 后台任务 | PostgreSQL + Node.js Worker |
| 开发目标 | 30 天 MVP |

**建议**：这版 PRD 已经足以作为下一步工程设计的输入。不要马上开发所有页面，建议先实现一个端到端的最小闭环：

上传商品图片 → 选择模板 → 生成文案 → Remotion 渲染 → 本地保存 MP4 → 下载视频

这个闭环跑通后，再开发用户管理、额度和支付功能。

下一步可以将这份 PRD 继续细化成一份技术设计文档（TDD），明确数据库 SQL、API 接口定义、模块职责、Worker 任务协议和 Remotion 渲染接口。
